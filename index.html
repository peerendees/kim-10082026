Deine erste eigene
Datenbank

In dieser Session bekommt deine Anwendung ein Gedächtnis. Wir bauen eine Kontakte-Datenbank mit Supabase, die Grundlage für dein eigenes CRM.

Online · 2 Stunden · Marcus Kunkel

Erst lesen, dann loslegen

Das hier ist kein Wettbewerb. Die Basis ist das vollständige Lernziel dieser Session. Wer nur die Basis schafft, hat alles erreicht, worum es geht, und geht mit einer funktionierenden Anwendung nach Hause.

Plus und Kür sind für alle, die schneller fertig sind und nicht warten wollen. Sie sind aufklappbar, damit sie niemanden ablenken. Es ist ausdrücklich in Ordnung, sie nie zu öffnen.

  • +Basis — machen wir gemeinsam. Immer sichtbar, nie eingeklappt.
  • ++Plus — vertieft den aktuellen Schritt. Für die Wartezeit.
  • +++Kür — für alle, die deutlich vorne sind.

Wo läuft eigentlich was

Die Frage kommt immer, deshalb vorweg. Es sind zwei getrennte Orte:

  • Supabase liegt in der Cloud. Dort wohnen die Tabelle und die Daten. Du erreichst es nur über den Browser.
  • Deine Anwendung läuft auf deinem Rechner, unter einer Adresse wie localhost:5173. Nur du siehst sie.

Verbunden werden beide über zwei Werte in einer Datei namens .env. Genau diese zwei Werte tauschen wir später einmal aus, und dann passiert etwas Interessantes.

00

Vorab, bitte vor der Session

ca. 15 Minuten · einmalig

Diese vier Punkte kosten dich vorher eine Viertelstunde und in der Session sonst eine Stunde. Wenn etwas klemmt, melde dich rechtzeitig.

1 · Node prüfen

Öffne ein Terminal und tippe:

node -v

Erscheint eine Versionsnummer wie v22.14.0, ist alles da. Erscheint „command not found" oder ähnliches, lade Node von nodejs.org und installiere die LTS-Version. Das ist ein normaler Installer zum Durchklicken, kein Terminal nötig.

Wahrscheinlich hast du Node schon. Claude Code läuft selbst darauf. Wer Claude Code benutzt, ist an dieser Stelle fertig.

2 · Supabase-Konto anlegen

Auf supabase.com registrieren. Kostenlos, Anmeldung über GitHub geht am schnellsten. Noch kein Projekt anlegen, das machen wir gemeinsam.

3 · Claude Code startklar

Claude Code muss laufen, und du solltest dich einmal eingeloggt haben. Wenn du seit der letzten Session nichts gemacht hast, kurz öffnen und prüfen.

4 · Linear-Konto

Auf linear.app registrieren, falls noch nicht geschehen. Wir nutzen es in der Session als Backlog für dein CRM.

Ein Hinweis zur Ehrlichkeit: Wenn du an diesen vier Punkten scheiterst, ist das kein Problem und kein Grund fernzubleiben. Komm trotzdem, schau zu, und arbeite die Seite hinterher in Ruhe durch. Sie bleibt stehen.
01

Das Projekt anlegen

ca. 10 Minuten

Wir starten mit einem frischen Projekt, nicht mit deiner bestehenden App. Zwei Wege führen zum selben Ergebnis, such dir einen aus.

Weg A · Über das Terminal

npm create vite@latest mein-crm -- --template react

Danach in den neuen Ordner wechseln, Abhängigkeiten laden und starten:

cd mein-crm
npm install
npm run dev

Weg B · Über Claude Code

Ordner anlegen, Claude Code darin starten und beauftragen:

Erstelle hier ein neues Vite-Projekt mit React für eine
Kontaktverwaltung. Starte danach den Entwicklungsserver und
sag mir, unter welcher Adresse ich die Seite sehe.

Im Terminal steht anschließend eine Adresse, meist http://localhost:5173. Öffne sie im Browser. Du siehst die Startseite von Vite. Das ist deine Anwendung, und ab jetzt bauen wir sie um.

Terminal offen lassen. Solange dort npm run dev läuft, läuft deine Seite. Schließt du das Fenster, ist die Seite weg. Für alle weiteren Befehle öffnest du ein zweites Terminal.
Linear Lege jetzt ein Projekt „Mein CRM" an und trage fünf Issues ein, eines pro Schritt dieser Seite. Wenn du magst, zusätzlich die Plus- und Kür-Aufgaben als eigene Issues. Am Ende der Session hast du damit einen echten Backlog, an dem du weiterarbeiten kannst.
02

Die Tabelle anlegen

ca. 15 Minuten

Jetzt zum zweiten Ort. In Supabase auf New project, einen Namen vergeben, ein Datenbank-Passwort setzen und als Region Frankfurt wählen. Das Passwort brauchst du heute nicht, notiere es trotzdem. Die Einrichtung dauert etwa eine Minute.

Danach links im Menü den SQL Editor öffnen, folgendes einfügen und ausführen:

create table kontakte (
  id         uuid primary key default gen_random_uuid(),
  created_at timestamptz default now(),
  name       text not null,
  firma      text,
  rolle      text,
  kontakt    text,
  notiz      text
);

alter table kontakte enable row level security;

create policy "lesen"    on kontakte for select using (true);
create policy "anlegen"  on kontakte for insert with check (true);
create policy "aendern"  on kontakte for update using (true);
create policy "loeschen" on kontakte for delete using (true);

Der obere Teil legt die Tabelle an. Der untere Teil regelt, wer was darf: lesen, anlegen, ändern, löschen. In deinem eigenen Projekt darfst du alles. Merk dir diese vier Zeilen, sie werden später wichtig.

Wechsle nun in den Table Editor. Deine Tabelle ist da, leer. Über Insert row trägst du zwei Kontakte von Hand ein. Die Felder id und created_at lässt du frei, die füllt die Datenbank selbst.

Das ist bereits ein Formular. Du hast gerade Daten gespeichert, ohne eine Zeile Code. Die Daten existieren jetzt unabhängig von jeder Anwendung. Genau das ist der Unterschied zu allem, was du bisher gebaut hast.
++ Plus Was bewirkt „not null"?

Versuche im Table Editor eine Zeile zu speichern, bei der du name leer lässt. Die Datenbank verweigert das und zeigt eine Fehlermeldung.

Das ist die Wirkung von not null: Die Regel steht in der Datenbank, nicht in deiner Anwendung. Auch wenn dein Formular später schlampig ist, kommt kein namenloser Kontakt durch. Alle anderen Felder dürfen leer bleiben.

Lies die Fehlermeldung einmal in Ruhe. Genau diese Meldung wirst du später in deiner Anwendung wiedersehen.

+++ Kür Selbst abfragen

Zurück in den SQL Editor. Hier fragst du Daten ab, statt Tabellen zu bauen. Probiere:

select name, firma, rolle
from kontakte
order by created_at desc;

Dann eine Einschränkung dazu:

select * from kontakte
where firma = 'Musterfirma GmbH';

Abfragen verändern nichts, du kannst hier nichts kaputtmachen. Und du siehst gleich wieder, was du hier tippst: Claude Code baut in Schritt 03 genau solche Abfragen in deine Anwendung ein.

03

Verbinden und anzeigen

ca. 25 Minuten

Jetzt bauen wir die Brücke zwischen deinem Rechner und der Cloud. Dafür brauchst du zwei Werte aus Supabase.

Die zwei Werte holen

In Supabase auf Project Settings, dort API. Du findest:

  • Project URL — sieht aus wie https://abcdefgh.supabase.co
  • anon public — ein sehr langer Schlüssel, beginnt meist mit eyJ
Finger weg vom service_role key. Der steht auf derselben Seite und umgeht alle Schutzregeln. Er gehört niemals in deine Anwendung und niemals in einen Chat. Wir brauchen ausschließlich den anon-Schlüssel.

Die .env anlegen

Im Hauptordner deines Projekts, dort wo auch die package.json liegt, legst du eine Datei namens .env an. Der Punkt am Anfang gehört dazu, der Dateiname besteht nur daraus.

VITE_SUPABASE_URL=https://DEINPROJEKT.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6...

Beide Platzhalter durch deine echten Werte ersetzen. Keine Anführungszeichen, keine Leerzeichen um das Gleichheitszeichen.

Die Anwendung bauen lassen

Jetzt übernimmt Claude Code. Beauftrage es mit dem vollständigen Kontext, also mit deinem Tabellenaufbau:

Ich habe eine Supabase-Datenbank mit einer Tabelle 'kontakte'.
Spalten: id (uuid), created_at (timestamptz), name (text, pflicht),
firma (text), rolle (text), kontakt (text), notiz (text).

Die Zugangsdaten stehen in der .env als VITE_SUPABASE_URL und
VITE_SUPABASE_ANON_KEY.

Installiere den Supabase-Client, verbinde die Anwendung und zeige
mir alle Kontakte als Liste an. Erklaere mir kurz, was du gemacht
hast und in welcher Datei die Verbindung steht.

Der letzte Satz ist kein Beiwerk. Lass dir erklären, was passiert ist, sonst hast du am Ende eine Anwendung, die funktioniert, und keine Ahnung warum.

Im Browser stehen jetzt die zwei Kontakte, die du vorhin von Hand eingetragen hast. Sie kommen nicht aus deinem Code, sie kommen aus Frankfurt.

Wenn nichts erscheint: Terminal anschauen. Nach dem Anlegen der .env muss der Entwicklungsserver einmal neu gestartet werden. Strg+C drückt ihn ab, npm run dev startet ihn wieder. Warum das so ist, klären wir in Schritt 05.
++ Plus Sortieren und zählen

Beauftrage Claude Code:

Sortiere die Kontaktliste nach created_at absteigend, sodass
die neuesten oben stehen. Zeige ausserdem ueber der Liste an,
wie viele Kontakte es insgesamt sind.

Schau dir danach im Code an, wo die Sortierung steht. Du findest dort ein .order(...), das dem order by aus dem SQL Editor entspricht. Der Zähler ist der interessantere Teil, ihn brauchst du gleich beim Umschalten.

+++ Kür Leerzustand und Ladezustand

Eine leere weiße Fläche ist die schlechteste Antwort, die eine Anwendung geben kann. Der Nutzer weiß nicht, ob sie lädt, leer ist oder kaputt.

Behandle zwei Faelle sauber: Waehrend die Daten geladen werden,
zeige einen Ladehinweis. Wenn keine Kontakte vorhanden sind,
zeige stattdessen den Hinweis 'Noch keine Kontakte. Trag deinen
ersten ein.' Zeige ausserdem eine verstaendliche Meldung an,
falls die Datenbank einen Fehler zurueckgibt.

Diese Arbeit zahlt sich in Schritt 05 aus. Du wirst dann als Einziger sofort sehen, was passiert ist.

Linear Issue für diesen Schritt auf Done ziehen. Zehn Sekunden, und du siehst deinen Fortschritt.
04

Kontakte eintragen

ca. 20 Minuten

Lesen kann deine Anwendung. Jetzt soll sie auch schreiben.

Baue ueber der Liste ein Formular mit Feldern fuer name, firma,
rolle, kontakt und notiz. Beim Absenden wird ein neuer Eintrag
in der Tabelle kontakte angelegt und die Liste aktualisiert sich,
ohne dass ich die Seite neu laden muss.

Trag einen echten Kontakt ein. Dann schau in Supabase in den Table Editor: Die Zeile steht dort. Dein Formular und der Table Editor schreiben in dieselbe Tabelle, sie sind nur zwei verschiedene Türen zum selben Raum.

++ Plus Formular aufräumen 
Leere das Formular nach dem erfolgreichen Absenden. Wenn das
Feld name leer ist, sende gar nicht erst ab, sondern zeige einen
Hinweis direkt am Feld. Zeige nach erfolgreichem Speichern kurz
eine Bestaetigung.

Beachte: Die Regel für den Pflichtnamen steht jetzt an zwei Stellen, in deinem Formular und in der Datenbank. Das ist kein Fehler, sondern richtig so. Das Formular ist die Höflichkeit, die Datenbank ist die Sicherheit.

+++ Kür Einträge löschen 
Ergaenze bei jedem Kontakt in der Liste einen Loeschen-Knopf.
Ein Klick entfernt den Eintrag aus der Datenbank und aus der
Liste. Frage vorher einmal nach, ob ich sicher bin.

Diese Aufgabe hat einen Hintergedanken. Behalte den Löschen-Knopf im Kopf, im nächsten Schritt wird er sich seltsam verhalten.

Linear Issue auf Done. Danach sammeln wir uns alle wieder, unabhängig davon, wo du stehst.
05

Der Abstecher

ca. 15 Minuten · alle gemeinsam

Hier gibt es kein Plus und keine Kür. Wir machen das alle gleichzeitig, weil es nur gemeinsam funktioniert.

Für diese Session existiert eine zweite Datenbank: das Verzeichnis der Masterclass. Sie hat exakt denselben Aufbau wie deine, dieselben sieben Spalten. Wir lassen deine Anwendung jetzt einmal darauf zeigen.

1 · Zweiten Block in die .env

Öffne deine .env und hänge unten an:

# Verzeichnis der Masterclass
#VITE_SUPABASE_URL=PLATZHALTER_VERZEICHNIS_URL
#VITE_SUPABASE_ANON_KEY=PLATZHALTER_VERZEICHNIS_KEY

Das Rautezeichen macht eine Zeile unwirksam. Die Datei enthält jetzt vier Zeilen, von denen zwei gelten und zwei schlafen.

2 · Umschalten

Setze vor deine beiden oberen Zeilen je ein # und entferne es bei den unteren beiden. Danach sieht die Datei so aus:

#VITE_SUPABASE_URL=https://DEINPROJEKT.supabase.co
#VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6...

# Verzeichnis der Masterclass
VITE_SUPABASE_URL=PLATZHALTER_VERZEICHNIS_URL
VITE_SUPABASE_ANON_KEY=PLATZHALTER_VERZEICHNIS_KEY

3 · Neu starten, nicht nur speichern

Ins Terminal wechseln, Strg+C drücken, dann:

npm run dev

Speichern allein reicht hier nicht. Vite liest die .env nur beim Start und backt die Werte fest in die Anwendung ein. Änderst du sie im laufenden Betrieb, passiert nichts.

4 · Ansehen

Seite neu laden. Deine Kontakte sind verschwunden, stattdessen steht dort das Verzeichnis der Gruppe.

Dein Code hat sich nicht geändert. Deine Anwendung hat sich nicht geändert. Du hast zwei Zeilen in einer Textdatei getauscht.

5 · Selbst eintragen

Trag dich über dein eigenes Formular ins Verzeichnis ein. Erfundene Daten sind ausdrücklich erlaubt und erwünscht. Dann warte einen Moment und lade neu: Du siehst die Einträge der anderen erscheinen.

Bitte keine echten Daten Dritter. Diese Datenbank ist offen, jeder in der Runde kann alles darin lesen. Sie wird nach der Session gelöscht. Trag nur ein, was öffentlich sein darf.

6 · Der Löschen-Knopf

Wer in der Kür einen Löschen-Knopf gebaut hat, probiert ihn jetzt aus. Es passiert nichts. Kein Fehler, keine Meldung, der Eintrag bleibt stehen.

Das ist kein Bug. Erinnerst du dich an die vier Regeln aus Schritt 02? In deiner eigenen Datenbank gibt es alle vier. Im Verzeichnis gibt es nur zwei: lesen und anlegen. Ändern und Löschen wurden nie erlaubt.

Gleicher Code, gleiche Anwendung, anderes Rechteprofil. Die Regeln stehen in der Datenbank, nicht in deinem Programm. Deshalb kann auch niemand sie umgehen, indem er deine Anwendung verändert.

7 · Zurückschalten

Rautezeichen wieder tauschen, oben weg, unten hin. Terminal: Strg+C, npm run dev. Deine eigenen Kontakte sind zurück.

06

Zurück zu deinem CRM

ca. 15 Minuten

Der Abstecher ist vorbei, ab jetzt geht es wieder nur um deine Anwendung. Sie kann Kontakte anzeigen und anlegen. Das ist die Basis, und damit ist das Lernziel dieser Session erreicht.

Was jetzt kommt, ist Ausbau. Nimm dir, was dich interessiert.

++ Plus Suchen 
Baue ueber der Liste ein Suchfeld. Waehrend ich tippe, wird die
Liste auf Kontakte eingeschraenkt, deren Name oder Firma den
Suchbegriff enthaelt. Gross- und Kleinschreibung soll dabei egal
sein.

Frag Claude Code anschließend, ob die Suche in der Datenbank oder im Browser stattfindet. Beides ist möglich, und der Unterschied wird wichtig, sobald du dreitausend Kontakte hast.

+++ Kür Bearbeiten und filtern 
Mache die Kontakte bearbeitbar: Ein Klick auf einen Eintrag
oeffnet die Felder zum Aendern, Speichern schreibt die Aenderung
in die Datenbank zurueck. Ergaenze ausserdem eine
Filtermoeglichkeit nach dem Feld rolle.

Das Bearbeiten funktioniert bei dir, weil du in Schritt 02 die Regel „aendern" angelegt hast. Im Verzeichnis hätte es nicht funktioniert.

+++ Kür Ins Netz stellen mit Coolify

Deine Anwendung läuft bisher ausschließlich auf deinem Rechner. Niemand sonst kann sie sehen. Zeit, das zu ändern.

Der Weg in Kürze: Projekt in ein Git-Repository legen, in Coolify eine neue Anwendung aus diesem Repository anlegen, als Build-Befehl npm run build und als Ausgabeverzeichnis dist angeben, Domain zuweisen.

Zwei Fallstricke. Erstens: Die .env gehört nicht ins Repository. Die beiden Werte trägst du stattdessen in Coolify als Umgebungsvariablen ein. Zweitens: Änderst du sie dort später, reicht kein Neustart, die Anwendung muss neu gebaut werden. Vite backt die Werte beim Bauen ein, genau wie du es vorhin gesehen hast.

Wenn du das heute nicht schaffst, ist das der beste denkbare Ausgang: Du hast ein konkretes, gut beschriebenes Issue für deinen Backlog.

Linear Der wichtigste Moment für dein Backlog. Was du heute nicht geschafft hast, ist kein Versäumnis, sondern deine Arbeitsliste. Trag ein, was dein CRM noch braucht: Firmen als eigene Tabelle, Kontakthistorie, Export, Anmeldung mit Passwort, Deployment. Damit verlässt du die Session nicht mit einer Übung, sondern mit einem Projekt.
07

Nach der Session

in deinem Tempo

Diese Seite bleibt online. Wenn du in der Session nicht mitgekommen bist oder gar nicht dabei warst, arbeite sie in Ruhe durch. Die Schritte funktionieren einzeln, nur der Abstecher in Schritt 05 braucht die Gruppe.

Drei Dinge, die du als Nächstes lernen solltest, in dieser Reihenfolge:

  • Anmeldung. Solange deine Anwendung keine Nutzer kennt, kann sie Daten nicht sinnvoll trennen. Supabase bringt das mit.
  • Echte Regeln statt „alles erlaubt". Die vier Zeilen aus Schritt 02 sind Prototyp-Einstellungen. Sobald es echte Daten sind, gehört dort hin: nur der Besitzer darf lesen.
  • Eine zweite Tabelle. Firmen getrennt von Kontakten. Damit lernst du Beziehungen, und ab da wird aus der Liste ein CRM.
Und der Satz vom Anfang gilt weiter: Basis reicht. Wer eine funktionierende Kontaktverwaltung mit eigener Datenbank gebaut hat, kann etwas, das er vor dieser Session nicht konnte. Alles Weitere ist Zugabe.
